# 技术说明

> 部署、架构、与上游示例的差异等细节。项目简介见 [根 README](../README.md)。

把本仓库里**能在无服务器环境运行**的语音能力整合成一个 Web 应用，补上声音复刻与音色管理，并用同一份代码同时支持 **Vercel** 和 **Render/Docker** 部署。

所有音频采集与播放都在浏览器完成 —— 仓库里约 15 个示例依赖 `pyaudio` / `javax.sound.sampled` / `wxPython`，在没有声卡的容器里必然崩溃。DashScope API Key 只存在于服务端。

## 功能

| # | Tab | 模型 | 状态 |
|---|-----|------|------|
| 1 | 实时语音对话 | `qwen-audio-3.0-realtime-plus` | ✅ 已实测，含历史重放 |
| 2 | 实时语音识别 | `fun-asr-realtime` | ✅ 已实测 |
| 3 | 语音合成 | 6 个可选模型 / 253 个音色 | ✅ 已实测 |
| 4 | 声音复刻 + 音色管理 | `VoiceEnrollmentService` | ⚠️ 需公网 HTTPS 才能复刻 |

### 已知问题

**Tab 4 声音复刻必须有公网地址。** `create_voice(url=...)` 要求 DashScope 能从公网下载样本，本地 `localhost` 无法满足，会返回 `BadRequest.InputDownloadFailed`。部署到 Render/Vercel 后即可工作。

实测还发现 DashScope 偶尔会在**下载已成功**（本应用访问日志里能看到 200）的情况下仍返回 `InputDownloadFailed`，对慢速源站（如隧道）尤其明显。`create_voice` 因此带 3 次重试，间隔 2 秒。

## 与原仓库的关键差异

**1. 声音复刻不再需要 OSS**

原示例要求你把录音传到 OSS 再把 URL 传给 `create_voice()`：

```
samples/speech-synthesizer/synthesize_speech_from_text_with_cloned_voice/python/record.py:39
    '... 请将录制好的音频上传到云端并获取可下载http链接。'
```

本应用自己就有公网 HTTPS 地址，所以它自己托管这段音频：

```
浏览器录音/上传 → 存入临时存储 → 生成 {PUBLIC_BASE_URL}/media/{uuid}.wav
                → create_voice(url=...) → DashScope 自行回源下载
                → 保留 15 分钟后自动清理
```

两种存储后端（`server/storage.py`）：

| backend | 适用 | 说明 |
|---|---|---|
| `local` | Render / Docker / 自有服务器 | 存临时目录，由 `GET /media/{uuid}` 提供 |
| `blob` | Vercel | 上传 Vercel Blob 拿公网 URL（函数文件系统只读且实例不粘滞，`local` 在 Vercel 上不可用）。store 必须是 Public，否则阿里云匿名下载不了 |

`STORAGE_BACKEND=auto`（默认）会在检测到 `BLOB_READ_WRITE_TOKEN` 或 Vercel 环境时自动选 `blob`。

用 `vercel` 官方 Python SDK（`pip install vercel`），**不是** PyPI 上那个同名的
个人封装 `vercel-blob` —— 它以前被放在 `[project.optional-dependencies]` 里，而
Vercel 的构建器只装 `dependencies`，结果一键部署出来的声音复刻 100% 报
`vercel-blob is required`。现在它是主依赖。

> 别手传 `token=None` 给 SDK。它的凭据解析顺序是「显式 token > 环境变量」，
> 传一个 `None` 进去会把 `BLOB_READ_WRITE_TOKEN` 那条兜底路径一起短路掉。

后端配错了不会在启动时炸 —— 缺依赖、缺 token、缺 `PUBLIC_BASE_URL` 都要等到用户
点「复刻」才失败。所以启动时会跑一次 `storage.check()`，有问题就打 WARNING，
`/healthz` 的 `storage_ok` 字段也会变成 `false`。

**2. Vercel 的 300 秒连接上限已处理**

Hobby 计划的 WebSocket 最长 300 秒且无法调高，到点上游 DashScope session 会被销毁，而实时对话的记忆完全在服务端。客户端因此持有对话文本历史，重连后发送 `client.replay`，由服务端翻译成一串 `conversation.item.create` 事件注入新 session：

```json
{"type":"client.replay","items":[{"role":"user","text":"…"},{"role":"assistant","text":"…"}]}
```

（`user` 用 `input_text`，`assistant` 用 `output_text`，上限 40 条 —— 见 `server/ws_chat.py`）

**3. 单端口**

原 `demo_app/web/server.py` 用 8080(HTTP) + 8081(WS) 两个端口；Render 只暴露一个。这里合并为单个 FastAPI 进程，静态页 / REST / 5 个 WebSocket 全部共用一个端口。Vercel 的 ASGI 中间件在 `websocket.accept()` 处终结 upgrade，同样只需要一个入口。

## 本地运行

```bash
cd webapp
python3 -m venv .venv && .venv/bin/pip install -e .

export DASHSCOPE_API_KEY=sk-xxx
export DASHSCOPE_WORKSPACE_ID=            # 实测公共端点即可，留空
export APP_PASSWORD=your-password
export PUBLIC_BASE_URL=http://localhost:8080   # 声音复刻需要

.venv/bin/uvicorn server.main:app --port 8080
```

打开 http://localhost:8080 。

> 浏览器麦克风在非 `localhost` 的 http 源上不可用。Vercel 和 Render 都自带 HTTPS，本地开发请用 `localhost`。

跑测试：

```bash
.venv/bin/pip install -e ".[dev]"
.venv/bin/python -m pytest tests -q         # 后端 221 个
node --test "tests/js/**/*.test.js"          # 前端 132 个，需要 Node 18+
```

前端测试用 Node 内置的测试运行器，**不需要 `npm install`**。仓库里那个 `package.json` 没有依赖也没有构建脚本，只有一行 `"type": "module"` —— 它存在是因为 `static/js/*.js` 是 ESM，而没有它 Node 会按 CommonJS 解析，import 直接失败。

## 环境变量

见 `.env.example`。最关键的几项：

| 变量 | 说明 |
|---|---|
| `DASHSCOPE_API_KEY` | 必填 |
| `DASHSCOPE_WORKSPACE_ID` | 可选。留空用公共端点；填写会把 SDK 端点改写到 `{workspace_id}.cn-beijing.maas.aliyuncs.com` |
| `APP_PASSWORD` | 访问密码，留空则关闭鉴权 |
| `SESSION_SECRET` | 签名会话 Cookie，留空则回落到 `APP_PASSWORD` |
| `PUBLIC_BASE_URL` | 部署后的公开地址，`STORAGE_BACKEND=local` 时必填 |
| `BLOB_READ_WRITE_TOKEN` | `STORAGE_BACKEND=blob` 时必填 |

### 文本标注用的 LLM（可选）

语音合成页的「AI 加情感标签 / AI 写口播稿」需要一个文本模型。**全部可配，换厂商不用改代码**：

| 变量 | 默认 | 说明 |
|---|---|---|
| `LLM_BASE_URL` | 百炼 compatible-mode | 任何 OpenAI 兼容端点 |
| `LLM_API_KEY` | 回落 `DASHSCOPE_API_KEY` | 独立凭据，与语音服务可以不同 |
| `LLM_MODELS` | `qwen-turbo:快速,qwen-plus:均衡` | `id:显示名` 列表，喂前端下拉 |
| `LLM_MODEL` | `LLM_MODELS` 第一项 | 默认选中 |
| `LLM_TIMEOUT_SECONDS` | `120` | 默认 300 太长，会烧光 Vercel 的函数预算；120 给长稿留了余量 |
| `LLM_MAX_TOKENS` / `LLM_TEMPERATURE` | `6000` / `0.3` | 上限不是预留，费用按实际生成计 |
| `TAGS_MAX_CHARS` | `4000` | 单次输入上限 |
| `TAGS_RICH_LEVELS` / `TAGS_DEFAULT_RICH_LEVEL` | 关/少/多，默认「少」 | 拟声标签档位 |
| `TAGS_LIMIT_*` | `20` / `60` / `120` | 限流：次数 / 窗口秒 / 锁定秒 |

「AI 写口播稿」表单的预制项也在服务端（改这里即可，不必动前端）：`TAGS_DURATIONS`、`TAGS_TONES`、`TAGS_AUDIENCES`、`TAGS_TOPIC_HINTS`，经 `/api/config` 的 `tags` 下发。时长的显示名带大致字数，按约 250 字/分钟换算 —— 「90 秒」对写稿的人没有直观概念。

时长 / 语气 / 听众服务端**不做枚举校验**，因为前端的每个下拉都带一个「自定义…」；校验了就把那条逃生口堵死了。模型 id、密度、拟声档位相反，必须校验。

时长的上限是按最长档位（15 分钟约 3750 字）定的：中文约一 token 一字，3750 字成稿要 4000+ token，所以 `LLM_MAX_TOKENS` 给到 6000、`TAGS_MAX_CHARS` 给到 4000，否则长稿只能写出来、标不了也发不完。

### 拟声标签的用量

`_RICH_BUDGET` 是一张 `(每 N 字最多一个, 全篇上限)` 的表，按「档位 × 密度」取值：

| | 稀疏 | 适中 | 密集 |
|---|---|---|---|
| **少**（默认） | 每 250 字 / ≤6 | 每 180 字 / ≤12 | 每 120 字 / ≤18 |
| **多** | 每 150 字 / ≤15 | 每 100 字 / ≤30 | 每 70 字 / ≤45 |

逐字率才是真正的控制项，上限只是防模型无视逐字率时无限插入的兜底。早期版本是固定「全篇最多 2 个」，长稿会显得干巴巴 —— 15 分钟的稿子里 2 个拟声标签救不了真人感。

设置位置：Render 在 Dashboard 的 Environment 或 `render.yaml`；Vercel 在 Project Settings（`vercel.json` 没有 env 块）；Docker/裸机用 `docker run -e` 或写进 `webapp/.env`。**这些都是 import 期求值，改完要重启。**

不配任何一项也能用：默认值指向百炼的 compatible-mode，直接复用现有的 `DASHSCOPE_API_KEY`。此时只有「快速标注」（本地规则）之外的两个按钮可用 —— 没配 Key 时它们会置灰并说明原因。

> 兼容性：个别推理模型拒收 `temperature`、或要求把 `max_tokens` 换成 `max_completion_tokens`。这类情况会在弹窗里显示上游的报错原文。

## 部署

### 一键部署

[![Deploy to Render](https://render.com/images/deploy-to-render-button.svg)](https://render.com/deploy?repo=https://github.com/hbpc002/speech-workbench)
[![Deploy with Vercel](https://vercel.com/button)](https://vercel.com/new/clone?repository-url=https://github.com/hbpc002/speech-workbench)
[![Deploy on Railway](https://railway.app/button.svg)](https://railway.app/new?repo=https://github.com/hbpc002/speech-workbench)

三个平台都必填 `DASHSCOPE_API_KEY`，但**声音复刻还各缺一样平台不会自动补的东西**：

| 平台 | 配置文件 | 自动处理 | 声音复刻还要手动做 |
|---|---|---|---|
| Render | `render.yaml` | 区域 singapore、健康检查、生成 `APP_PASSWORD` / `SESSION_SECRET` | 填 `PUBLIC_BASE_URL`（`render.yaml` 里是 `sync: false`） |
| Vercel | `vercel.json` | 区域 `hnd1`、Python runtime | 建 **Public** 的 Blob store 并 **Connect to Project** |
| Railway | 自动识别 `Dockerfile` | — | 填 `PUBLIC_BASE_URL` |

不补也能启动，四个页签里只有「声音复刻」会失败。启动日志里会有一条
`[boot] WARNING:` 说清楚缺什么，`/healthz` 的 `storage_ok` 也会是 `false`。

### Render

```bash
cd webapp
render blueprint launch      # 或在控制台 New → Blueprint，选 render.yaml
```

render.yaml 里 PUBLIC_BASE_URL 是 sync: false，部署时平台会提示填写，需要手动填成部署后的域名（如 https://speech-workbench.onrender.com），否则声音复刻会失败。

注意：免费版 512MB 内存、**5GB/月带宽**（2026-04 起从 100GB 削减），实时音频约 288MB/小时，即约 17 小时对话/月。

### Vercel

```bash
cd webapp
vercel
vercel env add DASHSCOPE_API_KEY
vercel env add DASHSCOPE_WORKSPACE_ID
vercel env add APP_PASSWORD
```

`vercel.json` 已把区域固定为 `hnd1`（东京）。DashScope 在 cn-beijing，选亚洲节点比默认的 `iad1`（华盛顿）延迟低很多；Hobby 只能选一个区域。

**声音复刻还需要一个 Vercel Blob store，且必须是 Public 的。** 三步：

1. 控制台 **Storage → Create Storage → Blob → Continue**，把 access 选成 **Public**。
2. 进 store 的 **Projects → Connect to Project**，勾选 Production 和 Preview。
3. 建完 store 后 `BLOB_READ_WRITE_TOKEN` 才会注入项目。

**access 一定要选 Public**，这是最容易踩的一个坑。阿里云下载复刻样本时是匿名
访问，不带任何凭据；而私有 store 的 URL 每次读都要鉴权。选成 Private 的话上传
直接被拒（`Cannot use public access on a private store`），而且这个属性**建的时候
就定死了、事后改不了**，CLI 也只有 `create-store` 没有改 access 的命令 —— 只能删掉
重建。

> 选 Public 不等于样本公开：文件名是 `uuid4().hex`，猜不到；`local` 后端的
> `/media/{uuid}` 同样是无鉴权的（原因一样，见 `server/main.py`），两者安全水位一致。

命令行等价操作：

```bash
vercel blob create-store speech-clone --access public
```

只建了 store 没连项目的话变量是空的，`storage.check()` 会在启动时告诉你；access
选错只能等上传时报错，`server/storage.py` 会把它换成中文并写明怎么重建。

自查：

```bash
vercel env ls    # 应该能看到 BLOB_READ_WRITE_TOKEN
```

> 环境变量是**部署时**注入的。在控制台加完变量必须 **Redeploy** 才对新请求生效，
> 不重新部署等于没加 —— 这个坑第一次遇到时表现为「明明配了还是报没有 token」。
> 变量也要加在部署实际用的那个环境上（生产域名用 Production，预览部署用 Preview）。
>
> 如果建 store 时在 Advanced Options 里改了 Environment Variable 的前缀，注入的
> 变量名就不是 `BLOB_READ_WRITE_TOKEN` 了，而是 `<前缀>_READ_WRITE_TOKEN`
> （比如 `MY_READ_WRITE_TOKEN`），本应用读不到。用默认前缀最省事。

Hobby 的 300 秒连接上限由上面的历史重放机制消化。Hobby 仅限非商业用途。

入口在 `pyproject.toml` 里声明：

```toml
[tool.vercel]
entrypoint = "server.main:app"
```

注意是 **`module:variable`** 格式，不是文件路径。写成 `server/main.py:app` 会被构建拒绝：

> `tool.vercel.entrypoint` is "server/main.py:app" but no matching module file was found. Use "module:object" format

对应关系：`server.main:app` 指向文件 `server/main.py`，这个路径同时也是 `vercel.json` 里 `functions` 的 key —— 两者必须一致。

Vercel 会从 `pyproject.toml` 的 `dependencies` 读取依赖，因此**不需要** `requirements.txt`。Python 版本默认 3.12，与项目要求一致。

### 自动构建镜像（GitHub Actions）

推送到 `main` 会自动跑 [`.github/workflows/docker.yml`](../.github/workflows/docker.yml)，依次：

1. **冒烟测试** —— 无密钥环境下导入应用，校验 5 条关键路由齐全、音色目录完整（当前 253 个 / 6 个模型）、`public_config()` 不泄漏密钥。测试不过不会出镜像。
2. **构建并推送** —— 推到 GitHub Container Registry，无需任何配置，权限用自带的 `GITHUB_TOKEN`。

拉取运行：

```bash
docker pull ghcr.io/hbpc002/speech-workbench:latest
docker run -p 8080:8080 -e DASHSCOPE_API_KEY=sk-xxx speech-workbench
```

推标签 `v1.2.3` 会额外产出 `1.2.3` / `1.2` / `1` 三种语义化标签。层缓存走 GitHub Actions cache，二次构建约 1 分钟。

每次构建产出的标签：

| 来源 | 例（提交 `e7d9925`） |
|---|---|
| 完整 sha | `e7d9925bc74be66f63290d5619e0df66e180e3c9` |
| 短 sha | `sha-e7d9925` |
| 分支 | `main` |
| 语义化版本 | 推 `v1.2.3` 得 `1.2.3`、`1.2`、`1` |
| 浮动 | `latest`（仅 `main` 分支） |

> 短 sha 的前缀是 `sha-` 而不是 `-`：Docker tag 不允许以 `-` 或 `.` 开头，`-e7d9925` 会被 buildx 拒绝，报 `invalid reference format`。

镜像默认是 Public，如需私有在 Settings → General → Packages 里改权限。若仓库是 Private，`docker pull` 时先执行 `echo $CR_PAT | docker login ghcr.io -u hbpc002 --password-stdin`。

#### 推送到 Docker Hub / 阿里云 ACR

两个目标默认关闭。开启需要**仓库变量**做开关 + **secrets** 提供凭据 —— job 级的 `if:` 不支持 `secrets` 上下文，所以开关只能用非机密的 variables。

| 目标 | 开关（Variables） | 凭据（Secrets） |
|---|---|---|
| Docker Hub | `ENABLE_DOCKERHUB` = `true` | `DOCKERHUB_USERNAME`、`DOCKERHUB_TOKEN` |
| 阿里云 ACR | `ENABLE_ACR` = `true` | `ACR_USERNAME`、`ACR_PASSWORD`、`ACR_IMAGE` |

两者都在 Settings → Secrets and variables → Actions 里配置。开关没开的 job 连 runner 都不会启动，不浪费配额。

`ACR_IMAGE` 只写命名空间，例如 `my-namespace`；完整镜像地址是 `registry.cn-hangzhou.aliyuncs.com/my-namespace`。杭州以外地域需同步改工作流里的 `ACR_REGISTRY`。

## 音色管理

声音复刻 Tab 提供：

- **浏览器录音 / 上传音频**，两者都产出一段 16kHz 单声道 WAV 样本
- **下载样本** —— 把当前样本存到本地。样本默认在复刻完成后 15 分钟被清理，先存下来才能重复使用
- **开始复刻** —— 提交样本，轮询式返回 `voice_id`
- **试音** —— 每个音色行内的按钮，直接用该 `voice_id` 合成并播放，文本取下方试听框内容
- **删除** —— 单条删除
- **清理全部** —— 一键回收全部音色，对应上游示例里的 `delete_voice_by_prefix()`。配额是每个百炼账号 1000 个自定义音色，创建免费，到上限后创建请求直接失败且系统不会自动淘汰最早的，只能手动删；单个音色连续 1 年没被合成请求用过则自动清理。删除不可逆，所以前端先列出要删的再让操作者确认。
- **样本自检** —— 见下文。官方音频要求是「推荐 10~20 秒、最长 60 秒、至少 5 秒连续清晰朗读」，`clip_check.js` 的阈值直接取自这几条。
- **音色管理** —— 改名与标签都是**本地**的（IndexedDB `voice-meta`），因为上游既没有名称字段也没有标签字段，`update_voice` 只能替换样本音频。上游返回的 `status`（DEPLOYING / OK / UNDEPLOYED）会直接显示，否则审核未通过的音色和能用的长得一模一样。
- **target_model 从 voice_id 解析** —— `list_voice` 只返回 `voice_id` / `gmt_create` / `gmt_modified` / `status`，**不含** `target_model`（只有 `query_voice` 有，而那要每个音色一次往返）。音色 ID 形如 `{target_model}-{prefix}-{唯一标识}`，所以 `voices.parse_clone_model()` 从 ID 里还原。匹配取最长前缀：模型 ID 本身含点和连字符，`qwen-audio-3.0-tts-flash` 也以 `qwen-audio-3.0-tts-` 开头。

## 语音合成工作台

文本按句拆分后逐句生成，每句可以单独 **生成 / 重新生成 / 播放 / 下载 / 删除**。
**下载完整音频** 始终把已生成的句子按阅读顺序拼成一个 WAV —— 重新生成其中几句之后，
下载到的仍是完整音频，而不是零散片段。

几个容易踩的点，已处理：

- **串行生成**。所有句子共用一条 WebSocket，一次只发一个请求并等 `tts.done` 再发下一个。并发连发会被静默丢弃或触发 `428`。
- **改文本不清空**。重新分句时按句子文本匹配，未改动的句子保留已有音频并从 IndexedDB 恢复，不会因为编辑一个标点就丢掉整篇。
- **刷新不丢**。生成的 PCM 存在 IndexedDB（不能用 localStorage：一句约 90 KB，5MB 字符串配额撑不住几句）。刷新后自动恢复并可直接下载。
- **等待连接就绪**。WebSocket 是异步连接的，先 `await whenOpen()` 再发送，否则请求会被无声丢弃。

### 情感标签（仅 qwen 系列）

写在文本里而不是指令里，是 qwen 独有的能力。切到 qwen 模型时界面会出现标签栏。

- **情感标签** 23 个：`[sad]` `[amazed]` `[angry]` `[excited]` `[sarcastic]` `[curious]` `[bored]` `[tired]` `[scornful]` `[shouting]` `[deep and loud shouting]` `[asmr]` `[panicked]` `[trembling]` `[mischievously]` `[empathetic]` `[whispers]` `[reluctantly]` `[crying]` `[serious]` `[very slowly]` `[very fast]` —— 作用于其后所有文字，直到遇到下一个
- **拟声标签** 7 个：`[gasp]` `[sighing]` `[clears throat]` `[giggles]` `[laughing]` `[cough]` `[snorts]` —— 只在插入位置产生一次效果

```
[excited]今天的天气真不错！[laughing]我们一起出去玩吧！
```

情感标签会跨句自动继承 —— 本工具按句合成，若不补齐则只有第一句带情绪。切到不支持标签的模型时，文本框里的标签会被自动删掉（`[1]` 这类普通方括号保留）。标签栏旁的 `?` 里内置了口播稿生成提示词。详见 [使用说明.md](../使用说明.md) 和 [口播稿提示词.md](../口播稿提示词.md)。

### 自动加情感标签

标签栏下方三个入口，结果一律**先弹窗预览、点「应用到文本框」才生效**，并保留快照供撤销：

- `POST /api/tts/tag` —— 给已有稿子插标签
- `POST /api/tts/script` —— 按主题写一篇新的带标签稿子
- 「快速标注」—— 纯前端关键词规则（`static/js/tag_rules.js`），不联网

拆成三层，各管一件事：

| 模块 | 职责 |
|---|---|
| `server/llm.py` | 通用能力：配置解析、模型白名单、`POST {base}/chat/completions`、错误映射。对「标签」零知识 |
| `server/tagger.py` | 只管提示词与清洗。标签清单**从 `voices.CONTROL_TAGS/RICH_TAGS` 运行时拼**，不再硬编码第三份 |
| `server/api_tagger.py` | 路由、pydantic 校验、限流 |

三个设计取舍：

1. **走裸 HTTP 而不是 dashscope.Generation。** 那个 SDK 只会打百炼；裸 HTTP 则对 DeepSeek、Kimi、GLM、OpenRouter、自建 vLLG 一视同仁。默认 base URL 指向百炼 compatible-mode，所以默认路径下代码也只有一条。
2. **模型 id 必须过服务端白名单**（`llm.resolve_model`），浏览器不能指定任意上游模型 —— 与 `tts_support.normalize_params` 丢弃未知参数是同一个理由。
3. **`sanitize()` 是必需的，不是装饰。** 模型会编造引擎不认识的标签（会被当普通文字念出来）、裹代码围栏、加「好的以下是…」，偶尔还会顺手改稿。因此：非白名单的 `[...]` 一律删除（用户自己原文里的 `[1]` 例外，按原样保留），围栏与客套剥离，并做一次「去标签后是否与原文逐字相同」的**防改写检测**，不一致就在预览里报警。
4. **`LLM_BASE_URL` 不出现在任何公开接口。** `/healthz` 无鉴权，自建 vLLM 的内网地址不该被看到；`/api/config` 只下发模型 id、显示名和一个 `configured` 布尔值。

## 音色

`cosyvoice-v3-flash` 的 **89 个系统音色**按场景分组展示在语音合成 Tab 的下拉里（标杆音色 / 社交陪伴 / 语音助手 / 客服 / 有声书 / 短视频配音 / 新闻播报 / 直播带货 / 诗词朗诵 / 童声 / 方言 / 出海营销），每项显示中文名、音色特质和语言范围。完整清单见 `server/voices.py`，来源是[官方音色列表](https://help.aliyun.com/zh/model-studio/cosyvoice-voice-list)。

音色 id **与模型绑定**：

- `cosyvoice-v3-flash` —— 上表 89 个
- `cosyvoice-v2` —— 用 `longxiaochun_v2` 等，**不带 `_v3` 后缀**
- `qwen-audio-3.0-realtime-*` —— `longanqian`、`longanlingxin` 等，喂给 cosyvoice 会返回错误码 **418**

复刻音色只能配合注册时相同的 `target_model` 使用。换 TTS 模型时要同步换音色列表。

### 重新生成与种子

`record.params` 在 `createRecord()` 时算好就冻结，`runSentence()` 每次都发同一份。因此同种子 + 同文本 = 逐字节相同的音频，「重新生成」会变成一个点了没反应的按钮。

指令拼装同理抽到了 `static/js/instruct.js`：合成页和复刻页都要发指令，模板差一个字就会变成 428，看起来像音色坏了。

解法是把种子拆成两层，逻辑放在纯模块 `static/js/seed_policy.js`（和 `tag_rules.js` 一样抽出来是为了能单测 —— `tab_tts.js` 依赖 `app.js`，而后者在模块顶层就碰 `document`，Node 里 import 会炸）：

- **基线种子** `record.params.seed` —— 首轮生成沿用它。留空时也会显式生成一个随机值并记下来，这样输入框里的「随机」占位符名副其实：任何一次生成都可复现，用户把数字填回去就能重来
- **单句种子** `sentence.seed` —— 之后每次重新生成都换一个新的。首次判断用 `sentence.seed == null` 而非 `=== undefined`，因为句子要过一遍 IndexedDB，字段可能变成 `null`，两种都表示「还没生成过」

记录卡副标题显示基线种子，单句「重新生成」的 tooltip 显示该句实际种子。

### 文本框的撤销

「撤销」统管两处改动文本框的操作：应用 AI 标签、清空文本。用栈（上限 20 步）而不是单槽，否则「先打标签再清空」只能撤一步。它放在生成按钮那一行而不是标签栏里 —— 标签栏只在 qwen 模型下显示，藏进去的话切到 cosyvoice 后清空文本就不可逆了。

## 安全说明

- API Key 只在服务端，浏览器拿不到
- 语音 Key 与文本标注 Key 是**两个独立凭据**，`redact.scrub` 两个都逐字脱敏 —— 换模型厂商后上游报错回显新 Key 也不会漏出去
- 标注接口按 IP 限流（`TAGS_LIMIT_*`），防止刷接口烧 token；限流计数不分成功失败，成本两种情况都已经产生
- `normalize_params` 对非有限数值（`"nan"` / `"inf"`）直接丢弃。`float()` 接受它们不报错，但紧接着的 `int()` 会抛未被捕获的 `ValueError` / `OverflowError`，那会让一个畸形帧变成 500 而不是被夹紧
- `/media/{name}` 无鉴权，因为 DashScope 回源下载时无法带 Cookie；文件名是 uuid4 十六进制，且复刻完成即删除
- 音色配额有限，建议定期清理（对应 `run.py:66-69` 的 `delete_voice_by_prefix`）
- 复刻他人音色前请确认已获得对方同意
