# 技术说明

> 部署、架构、与上游示例的差异等细节。项目简介见 [根 README](../README.md)。

把本仓库里**能在无服务器环境运行**的语音能力整合成一个 Web 应用，补上声音复刻与音色管理，并用同一份代码同时支持 **Vercel** 和 **Render/Docker** 部署。

所有音频采集与播放都在浏览器完成 —— 仓库里约 15 个示例依赖 `pyaudio` / `javax.sound.sampled` / `wxPython`，在没有声卡的容器里必然崩溃。DashScope API Key 只存在于服务端。

## 功能

| # | Tab | 模型 | 状态 |
|---|-----|------|------|
| 1 | 实时语音对话 | `qwen-audio-3.0-realtime-plus` | ✅ 已实测，含历史重放 |
| 2 | 实时语音识别 | `fun-asr-realtime` | ✅ 已实测 |
| 3 | 语音合成 | 6 个可选模型 / 253 个音色 | ✅ 已实测 |
| 4 | 声音复刻 + 音色管理 | `VoiceEnrollmentService` | ⚠️ 需公网 HTTPS 才能复刻 |

### 已知问题

**Tab 4 声音复刻必须有公网地址。** `create_voice(url=...)` 要求 DashScope 能从公网下载样本，本地 `localhost` 无法满足，会返回 `BadRequest.InputDownloadFailed`。部署到 Render/Vercel 后即可工作。

实测还发现 DashScope 偶尔会在**下载已成功**（本应用访问日志里能看到 200）的情况下仍返回 `InputDownloadFailed`，对慢速源站（如隧道）尤其明显。`create_voice` 因此带 3 次重试，间隔 2 秒。

## 与原仓库的关键差异

**1. 声音复刻不再需要 OSS**

原示例要求你把录音传到 OSS 再把 URL 传给 `create_voice()`：

```
samples/speech-synthesizer/synthesize_speech_from_text_with_cloned_voice/python/record.py:39
    '... 请将录制好的音频上传到云端并获取可下载http链接。'
```

本应用自己就有公网 HTTPS 地址，所以它自己托管这段音频：

```
浏览器录音/上传 → 存入临时存储 → 生成 {PUBLIC_BASE_URL}/media/{uuid}.wav
                → create_voice(url=...) → DashScope 自行回源下载
                → 保留 15 分钟后自动清理
```

两种存储后端（`server/storage.py`）：

| backend | 适用 | 说明 |
|---|---|---|
| `local` | Render / Docker / 自有服务器 | 存临时目录，由 `GET /media/{uuid}` 提供 |
| `blob` | Vercel | 上传 Vercel Blob 拿公网 URL（函数文件系统只读且实例不粘滞，`local` 在 Vercel 上不可用）。store 必须是 Public，否则阿里云匿名下载不了 |

`STORAGE_BACKEND=auto`（默认）会在检测到 `BLOB_READ_WRITE_TOKEN` 或 Vercel 环境时自动选 `blob`。

用 `vercel` 官方 Python SDK（`pip install vercel`，本项目要求 `>=0.12,<0.13`），
**不是** PyPI 上那个同名的个人封装 `vercel-blob` —— 它以前被放在
`[project.optional-dependencies]` 里，而 Vercel 的构建器只装 `dependencies`，结果
一键部署出来的声音复刻 100% 报 `vercel-blob is required`。现在它是主依赖。

0.12 把旧的 `AsyncBlobClient` / `BlobNoTokenProvidedError` 换成了模块级
`put_blob` / `BlobCredentialsError`，代码用的是新 API。凭据只从环境变量
（`BLOB_READ_WRITE_TOKEN` / `VERCEL_BLOB_READ_WRITE_TOKEN`）解析，没有显式 token
参数；`config._load_dotenv()` 会把 `.env` 写进 `os.environ`，行为与之前一致。
启动自检不只看 `import vercel.blob`，还要求模块里存在 `put_blob`，所以装了 0.11
会在启动日志里直接报「版本过旧」，而不是等到点「复刻」才失败。

后端配错了不会在启动时炸 —— 缺依赖、缺 token、缺 `PUBLIC_BASE_URL` 都要等到用户
点「复刻」才失败。所以启动时会跑一次 `storage.check()`，有问题就打 WARNING，
`/healthz` 的 `storage_ok` 字段也会变成 `false`。

**2. Vercel 的 300 秒连接上限已处理**

Hobby 计划的 WebSocket 最长 300 秒且无法调高，到点上游 DashScope session 会被销毁，而实时对话的记忆完全在服务端。客户端因此持有对话文本历史，重连后发送 `client.replay`，由服务端翻译成一串 `conversation.item.create` 事件注入新 session：

```json
{"type":"client.replay","items":[{"role":"user","text":"…"},{"role":"assistant","text":"…"}]}
```

（`user` 用 `input_text`，`assistant` 用 `output_text`，上限 40 条 —— 见 `server/ws_chat.py`）

**3. 单端口**

原 `demo_app/web/server.py` 用 8080(HTTP) + 8081(WS) 两个端口；Render 只暴露一个。这里合并为单个 FastAPI 进程，静态页 / REST / 5 个 WebSocket 全部共用一个端口。Vercel 的 ASGI 中间件在 `websocket.accept()` 处终结 upgrade，同样只需要一个入口。

## 本地运行

```bash
cd webapp
python3 -m venv .venv && .venv/bin/pip install -e .

export DASHSCOPE_API_KEY=sk-xxx
export DASHSCOPE_WORKSPACE_ID=llm-xxxxxxxx  # 业务空间 Key 必填，形如 llm-xxxxxxxx
export APP_PASSWORD=your-password
export PUBLIC_BASE_URL=http://localhost:8080   # 声音复刻需要

.venv/bin/uvicorn server.main:app --port 8080
```

打开 http://localhost:8080 。

> 浏览器麦克风在非 `localhost` 的 http 源上不可用。Vercel 和 Render 都自带 HTTPS，本地开发请用 `localhost`。

跑测试：

```bash
.venv/bin/pip install -e ".[dev]"
.venv/bin/python -m pytest tests -q         # 后端 286 个
node --test "tests/js/**/*.test.js"          # 前端 279 个，需要 Node 18+
node tests/e2e_boot.mjs                     # 端到端：真 app.js 对真 uvicorn，需要 .venv
```

前端测试用 Node 内置的测试运行器，**不需要 `npm install`**。仓库里那个 `package.json` 没有依赖也没有构建脚本，只有一行 `"type": "module"` —— 它存在是因为 `static/js/*.js` 是 ESM，而没有它 Node 会按 CommonJS 解析，import 直接失败。

## 环境变量

见 `.env.example`。最关键的几项：

| 变量 | 说明 |
|---|---|
| `DASHSCOPE_API_KEY` | 必填 |
| `DASHSCOPE_WORKSPACE_ID` | `sk-ws-` 开头的业务空间 Key **必填**。填了会把 SDK 端点改写到 `https://{workspace_id}.cn-beijing.maas.aliyuncs.com`。格式是 `llm-xxxxxxxx`，在百炼控制台「业务空间 → 业务空间详情」查。**填错会让所有 DashScope 调用挂到超时**（域名解析不了），现象是「上游不可达」而不是「填错了」，所以启动时会校验格式并打 WARNING。<br>留空则语音合成和实时对话仍可用（实测两个端点都通），但音色列表/复刻会报 `ModelNotFound` —— `VoiceEnrollmentService` 只认工作空间端点，等于整个 Tab 6 不可用 |
| `APP_PASSWORD` | 访问密码，留空则关闭鉴权 |
| `SESSION_SECRET` | 签名会话 Cookie，留空则回落到 `APP_PASSWORD` |
| `PUBLIC_BASE_URL` | 部署后的公开地址，`STORAGE_BACKEND=local` 时必填 |
| `BLOB_READ_WRITE_TOKEN` | `STORAGE_BACKEND=blob` 时必填 |

### 文本标注用的 LLM（可选）

语音合成页的「AI 加情感标签 / AI 写口播稿」需要一个文本模型。**全部可配，换厂商不用改代码**：

| 变量 | 默认 | 说明 |
|---|---|---|
| `LLM_BASE_URL` | 百炼 compatible-mode | 任何 OpenAI 兼容端点 |
| `LLM_API_KEY` | 回落 `DASHSCOPE_API_KEY` | 独立凭据，与语音服务可以不同 |
| `LLM_MODELS` | `qwen3.8-flash:均衡,qwen3.7-flash:备用` | `id:显示名` 列表，喂前端下拉。**只列实测调得通的**：百炼 Key 带模型白名单，不在名单里的模型报 403 `AccessDenied: Access denied by API-Key restrictions.` 而不是 404，摆在下拉里就是「点了就报错」。白名单在百炼控制台 → API-KEY 管理 配，放开后追加 id 即可 |
| `LLM_MODEL` | `LLM_MODELS` 第一项 | 默认选中 |
| `LLM_TIMEOUT_SECONDS` | `120` | 默认 300 太长，会烧光 Vercel 的函数预算；120 给长稿留了余量 |
| `LLM_MAX_TOKENS` / `LLM_TEMPERATURE` | `6000` / `0.3` | 上限不是预留，费用按实际生成计 |
| `TAGS_MAX_CHARS` | `4000` | 单次输入上限 |
| `TAGS_RICH_LEVELS` / `TAGS_DEFAULT_RICH_LEVEL` | 关/少/多，默认「少」 | 拟声标签档位 |
| `TAGS_LIMIT_*` | `20` / `60` / `120` | 限流：次数 / 窗口秒 / 锁定秒 |

「AI 写口播稿」表单的预制项也在服务端（改这里即可，不必动前端）：`TAGS_DURATIONS`、`TAGS_TONES`、`TAGS_AUDIENCES`、`TAGS_TOPIC_HINTS`，经 `/api/config` 的 `tags` 下发。时长的显示名带大致字数，按约 250 字/分钟换算 —— 「90 秒」对写稿的人没有直观概念。

时长 / 语气 / 听众服务端**不做枚举校验**，因为前端的每个下拉都带一个「自定义…」；校验了就把那条逃生口堵死了。模型 id、密度、拟声档位相反，必须校验。

时长的上限是按最长档位（15 分钟约 3750 字）定的：中文约一 token 一字，3750 字成稿要 4000+ token，所以 `LLM_MAX_TOKENS` 给到 6000、`TAGS_MAX_CHARS` 给到 4000，否则长稿只能写出来、标不了也发不完。

### 拟声标签的用量

`_RICH_BUDGET` 是一张 `(每 N 字最多一个, 全篇上限)` 的表，按「档位 × 密度」取值：

| | 稀疏 | 适中 | 密集 |
|---|---|---|---|
| **少**（默认） | 每 250 字 / ≤6 | 每 180 字 / ≤12 | 每 120 字 / ≤18 |
| **多** | 每 150 字 / ≤15 | 每 100 字 / ≤30 | 每 70 字 / ≤45 |

逐字率才是真正的控制项，上限只是防模型无视逐字率时无限插入的兜底。早期版本是固定「全篇最多 2 个」，长稿会显得干巴巴 —— 15 分钟的稿子里 2 个拟声标签救不了真人感。

设置位置：Render 在 Dashboard 的 Environment 或 `render.yaml`；Vercel 在 Project Settings（`vercel.json` 没有 env 块）；Docker/裸机用 `docker run -e` 或写进 `webapp/.env`。**这些都是 import 期求值，改完要重启。**

不配任何一项也能用：默认值指向百炼的 compatible-mode，直接复用现有的 `DASHSCOPE_API_KEY`。此时只有「快速标注」（本地规则）之外的两个按钮可用 —— 没配 Key 时它们会置灰并说明原因。

> 兼容性：个别推理模型拒收 `temperature`、或要求把 `max_tokens` 换成 `max_completion_tokens`。这类情况会在弹窗里显示上游的报错原文。

## 部署

### 一键部署

[![Deploy to Render](https://render.com/images/deploy-to-render-button.svg)](https://render.com/deploy?repo=https://github.com/hbpc002/speech-workbench)
[![Deploy with Vercel](https://vercel.com/button)](https://vercel.com/new/clone?repository-url=https://github.com/hbpc002/speech-workbench)
[![Deploy on Railway](https://railway.app/button.svg)](https://railway.app/new?repo=https://github.com/hbpc002/speech-workbench)

三个平台都必填 `DASHSCOPE_API_KEY`，但**声音复刻还各缺一样平台不会自动补的东西**：

| 平台 | 配置文件 | 自动处理 | 声音复刻还要手动做 |
|---|---|---|---|
| Render | `render.yaml` | 区域 singapore、健康检查、生成 `APP_PASSWORD` / `SESSION_SECRET` | 填 `PUBLIC_BASE_URL`（`render.yaml` 里是 `sync: false`） |
| Vercel | `vercel.json` | 区域 `hkg1`、Python runtime | 建 **Public** 的 Blob store 并 **Connect to Project** |
| Railway | 自动识别 `Dockerfile` | — | 填 `PUBLIC_BASE_URL` |

不补也能启动，四个页签里只有「声音复刻」会失败。启动日志里会有一条
`[boot] WARNING:` 说清楚缺什么，`/healthz` 的 `storage_ok` 也会是 `false`。

### Render

```bash
cd webapp
render blueprint launch      # 或在控制台 New → Blueprint，选 render.yaml
```

render.yaml 里 PUBLIC_BASE_URL 是 sync: false，部署时平台会提示填写，需要手动填成部署后的域名（如 https://speech-workbench.onrender.com），否则声音复刻会失败。

注意：免费版 512MB 内存、**5GB/月带宽**（2026-04 起从 100GB 削减），实时音频约 288MB/小时，即约 17 小时对话/月。

### Vercel

```bash
cd webapp
vercel
vercel env add DASHSCOPE_API_KEY
vercel env add DASHSCOPE_WORKSPACE_ID
vercel env add APP_PASSWORD
```

`vercel.json` 已把区域固定为 `hkg1`（香港）。DashScope 在 cn-beijing，选亚洲节点比默认的 `iad1`（华盛顿）近得多；Hobby 只能选一个区域。

> **为什么从 `hnd1`（东京）换成 `hkg1`（香港）**：实测从 hnd1 出站到阿里云北京会出现
> `[Errno 110] Connection timed out` —— TCP SYN 被丢弃，而 SDK 的 WebSocket 握手只等
> 5 秒，于是每句合成报 `websocket connection could not established within 5s`。
> 这是跨境线路问题，不是延迟问题。香港到大陆有直连对等，命中概率明显更高。
> 但它只是缓解：只要有跨境这一段，就可能再犯。彻底解决是把服务放在境内
> （见 [Docker 部署](#docker)），Vercel 上任何区域都做不到。

**声音复刻还需要一个 Vercel Blob store，且必须是 Public 的。** 三步：

1. 控制台 **Storage → Create Storage → Blob → Continue**，把 access 选成 **Public**。
2. 进 store 的 **Projects → Connect to Project**，勾选 Production 和 Preview。
3. 建完 store 后 `BLOB_READ_WRITE_TOKEN` 才会注入项目。

**access 一定要选 Public**，这是最容易踩的一个坑。阿里云下载复刻样本时是匿名
访问，不带任何凭据；而私有 store 的 URL 每次读都要鉴权。选成 Private 的话上传
直接被拒（`Cannot use public access on a private store`），而且这个属性**建的时候
就定死了、事后改不了**，CLI 也只有 `create-store` 没有改 access 的命令 —— 只能删掉
重建。

> 选 Public 不等于样本公开：文件名是 `uuid4().hex`，猜不到；`local` 后端的
> `/media/{uuid}` 同样是无鉴权的（原因一样，见 `server/main.py`），两者安全水位一致。

命令行等价操作：

```bash
vercel blob create-store speech-clone --access public
```

只建了 store 没连项目的话变量是空的，`storage.check()` 会在启动时告诉你；access
选错只能等上传时报错，`server/storage.py` 会把它换成中文并写明怎么重建。

自查：

```bash
vercel env ls    # 应该能看到 BLOB_READ_WRITE_TOKEN
```

> 环境变量是**部署时**注入的。在控制台加完变量必须 **Redeploy** 才对新请求生效，
> 不重新部署等于没加 —— 这个坑第一次遇到时表现为「明明配了还是报没有 token」。
> 变量也要加在部署实际用的那个环境上（生产域名用 Production，预览部署用 Preview）。
>
> 如果建 store 时在 Advanced Options 里改了 Environment Variable 的前缀，注入的
> 变量名就不是 `BLOB_READ_WRITE_TOKEN` 了，而是 `<前缀>_READ_WRITE_TOKEN`
> （比如 `MY_READ_WRITE_TOKEN`），本应用读不到。用默认前缀最省事。

Hobby 的 300 秒连接上限由上面的历史重放机制消化。Hobby 仅限非商业用途。

入口在 `pyproject.toml` 里声明：

```toml
[tool.vercel]
entrypoint = "server.main:app"
```

注意是 **`module:variable`** 格式，不是文件路径。写成 `server/main.py:app` 会被构建拒绝：

> `tool.vercel.entrypoint` is "server/main.py:app" but no matching module file was found. Use "module:object" format

对应关系：`server.main:app` 指向文件 `server/main.py`，这个路径同时也是 `vercel.json` 里 `functions` 的 key —— 两者必须一致。

Vercel 会从 `pyproject.toml` 的 `dependencies` 读取依赖，因此**不需要** `requirements.txt`。Python 版本默认 3.12，与项目要求一致。

### Cloudflare（免费层跑不了）

**结论：这个应用不能在 Cloudflare 免费层上运行。** 不是配置没调对，是下面几条同时成立。

**1. 出站 Python socket 在 Python Workers 上不存在。** Python Workers 跑在 Pyodide（CPython 的 WebAssembly 移植）里，而 Pyodide 明确不支持浏览器环境的 socket：

> By default, Pyodide does not support sockets in the browser. … This feature is only available in Node.js and is not supported in browsers.

Pyodide 的 socket 开关（`useNodeSockFS()`）只在 Node.js 下有效，Workers 的 isolate 不是 Node.js。本应用有四处依赖 socket：

| 位置 | 依赖 |
|---|---|
| `server/ws_chat.py` | `websockets.connect()` 直连 DashScope realtime |
| `server/llm.py`、`server/api_voices.py` | `requests`（标注 / 写稿 / 列举音色） |
| `server/ws_asr.py`、`server/tts_support.py` | `dashscope` SDK（内部走 `aiohttp` / `websocket-client`） |
| `server/upstream_probe.py` | 裸 `socket` + `ssl`，探测 DNS / TCP / TLS |

Cloudflare 官方的 `python-workers-examples/websocket-stream-consumer` 就是这条限制的旁证：它连出站 WebSocket 时用的是 `js.WebSocket.new(url)`（JS FFI），而不是 Python 的 `websockets`，源码注释里也写着「将来会提供原生 Python websocket API」—— 也就是说现在没有。改走 FFI 意味着把上面四处全部改写成 JS `fetch` / `WebSocket`，包括 `dashscope` SDK 的整条调用链，那是重写而不是换部署配置。

**2. 线程不可用，而这套代码依赖线程。** Workers 运行时是单线程的，`threading` 在 Python Workers 里「可以 import 但不能工作」，启动线程会直接抛 `RuntimeError: can't start new thread`（Cloudflare 自己的 `anyio.to_thread` 补丁就是为此把阻塞调用改成内联执行）。本应用有两处绕不开：

- `server/api_voices.py` 的 `_call_with_timeout()` 用 `ThreadPoolExecutor` 给阻塞的 SDK 调用套硬超时；
- `server/ratelimit.py` 用 `threading.Lock` 保护限流表。

**3. 免费层本身的额度也不够。** 即使前两条不存在：

| 限制 | 免费层 | 这个应用需要什么 |
|---|---|---|
| CPU 时间 / 请求 | 10 ms | Pyodide 冷启动本身就按秒计 |
| 内存 / isolate | 128 MB | — |
| 出站连接 / 请求 | 6 | 实时对话要同时持有浏览器 + 上游两条长连 |
| Containers | **不提供** | 唯一能原样跑这套 Python 的形态 |

Containers（可以直接跑本仓库的 `Dockerfile`）只在 Workers Paid（$5/月起）提供，免费层连入口都没有。顺带一提：静态资源（`static/` 共 276 KB）和入站 WebSocket 升级本身不是问题 —— Cloudflare 的 Python ASGI 入口（`workers.asgi.entrypoint`）支持 `websocket.accept`，`server/main.py` 的 `/ws/chat`、`/ws/asr`、`/ws/tts` 这三个端点在这一侧没问题。卡住的是出站那一段。

**那什么能用？** 依次是 Render 免费版、Vercel Hobby、Railway，或任何一台自己的机器跑 `Dockerfile` —— 这三条都已经在仓库里配好，见上面的小节。想要 Cloudflare 的全球网络，就得升到 Workers Paid 用 Containers，把 `Dockerfile` 原样部署；只上 Workers/Pages 不行。

> 附带一条：即使迁到 Containers，`PUBLIC_BASE_URL` 和 `STORAGE_BACKEND=local` 的行为与上面的 Docker 部署一致；Vercel Blob 那条 `blob` 路径在 Cloudflare 上不适用，样本要改存 R2（免费层 10 GB-month、100 万次 Class A、1000 万次 Class B，出站免费）。

## 音色管理

声音复刻 Tab 提供：

- **浏览器录音 / 上传音频**，两者都产出一段 16kHz 单声道 WAV 样本
- **下载样本** —— 把当前样本存到本地。样本默认在复刻完成后 15 分钟被清理，先存下来才能重复使用
- **开始复刻** —— 提交样本，轮询式返回 `voice_id`
- **试音** —— 每个音色行内的按钮，直接用该 `voice_id` 合成并播放，文本取下方「生成文本」框内容
- **删除** —— 单条删除
- **清理全部** —— 一键回收全部音色，对应上游示例里的 `delete_voice_by_prefix()`。配额是每个百炼账号 1000 个自定义音色，创建免费，到上限后创建请求直接失败且系统不会自动淘汰最早的，只能手动删；单个音色连续 1 年没被合成请求用过则自动清理。删除不可逆，所以前端先列出要删的再让操作者确认。
- **样本自检** —— 见下文。官方音频要求是「推荐 10~20 秒、最长 60 秒、至少 5 秒连续清晰朗读」，`clip_check.js` 的阈值直接取自这几条。
- **音色管理** —— 改名与标签都是**本地**的（IndexedDB `voice-meta`），因为上游既没有名称字段也没有标签字段，`update_voice` 只能替换样本音频。上游返回的 `status`（DEPLOYING / OK / UNDEPLOYED）会直接显示，否则审核未通过的音色和能用的长得一模一样。
- **列表失败时不至于整个页签报废** —— `GET /api/voices` 超时会**回落到上一次成功的列表**并打上 `stale: true`（前端显示「显示的是上一次成功获取的列表」）。这一条比 504 更有用：页签还能看到自己复刻过什么，还能删除 —— 而删除是唯一和上游配额挂钩的操作。没有任何缓存时返回 504，**绝不返回空列表**，因为空列表等于谎称「你没有音色」，可能诱导操作者误建。失败本身也会被缓存 15 秒，否则每次刷新都要重新付一遍超时；「刷新列表」按钮发 `refresh=true` 绕过成功/失败两级缓存 —— 一个刷不了新的刷新按钮本身就是 bug。
- **列表还有一层浏览器缓存** —— 服务端那两层缓存挡不住冷启动：Vercel 上函数实例可能是刚起来的，服务端并没有上次成功的列表可回落，于是首屏要么空要么等满 20 秒超时，操作者学会了一上来就手点「刷新列表」。所以前端把上一次拿到的列表（IndexedDB `voice-list`，一条记录）先画出来，再后台刷新覆盖，横幅写明缓存时间。写缓存的时机有四处：网络成功、`deleteOne()` 成功后本地摘除、`clearAll()` 成功后置空、`clone()` 成功后先乐观插入一条 `DEPLOYING`。删除和清理改成**只改本地列表、不再回头刷一次网络**，既是省一次往返，也是上游不可达时界面仍然正确的原因。
- **target_model 从 voice_id 解析** —— `list_voice` 只返回 `voice_id` / `gmt_create` / `gmt_modified` / `status`，**不含** `target_model`（只有 `query_voice` 有，而那要每个音色一次往返）。音色 ID 形如 `{target_model}-{prefix}-{唯一标识}`，所以 `voices.parse_clone_model()` 从 ID 里还原。匹配取最长前缀：模型 ID 本身含点和连字符，`qwen-audio-3.0-tts-flash` 也以 `qwen-audio-3.0-tts-` 开头。

## 语音合成工作台

文本按句拆分后逐句生成，每句可以单独 **生成 / 重新生成 / 播放 / 下载 / 删除**。
**下载完整音频** 始终把已生成的句子按阅读顺序拼成一个 WAV —— 重新生成其中几句之后，
下载到的仍是完整音频，而不是零散片段。

几个容易踩的点，已处理：

- **串行生成**。所有句子共用一条 WebSocket，一次只发一个请求并等 `tts.done` 再发下一个。并发连发会被静默丢弃或触发 `428`。
- **改文本不清空**。重新分句时按句子文本匹配，未改动的句子保留已有音频并从 IndexedDB 恢复，不会因为编辑一个标点就丢掉整篇。
- **刷新不丢**。生成的 PCM 存在 IndexedDB（不能用 localStorage：一句约 90 KB，5MB 字符串配额撑不住几句）。刷新后自动恢复并可直接下载。
- **等待连接就绪**。WebSocket 是异步连接的，先 `await whenOpen()` 再发送，否则请求会被无声丢弃。
- **上游连接超时**。SDK 的 WebSocket 握手写死等 5 秒，跨境线路偶尔整段握手都推进不了，报 `websocket connection could not established within 5s`。现在只对「连接超时」重试（默认 3 次、指数退避 + 抖动），其余失败（模型不存在、参数错误）立即上抛，避免重复计费。最后一次仍失败时，主动探测同一端点，把卡在 **DNS / TCP / TLS** 哪一段写进浏览器调试抽屉的 `debug.upstream_probe`。
  > `[Errno 110] Connection timed out` 是 SYN 被丢弃，不是延迟 —— 换区域只能换条线路，不能根治；把服务放在境内才是正解。

TTS 连接相关配置：

| 变量 | 默认 | 说明 |
|---|---|---|
| `TTS_CONNECT_ATTEMPTS` | `3` | 连接超时最多试几次（SDK 每次固定 5s） |
| `TTS_CONNECT_BACKOFF_SECONDS` / `TTS_CONNECT_BACKOFF_MAX_SECONDS` | `0.5` / `2` | 指数退避起点与封顶 |
| `TTS_CONNECT_JITTER_SECONDS` | `0.25` | 抖动，设 0 关闭 |
| `TTS_PROBE_TIMEOUT_SECONDS` | `3` | 失败后的探测超时，设 0 关闭 |

### 情感标签（仅 qwen 系列）

写在文本里而不是指令里，是 qwen 独有的能力。切到 qwen 模型时界面会出现标签栏。

- **情感标签** 23 个：`[sad]` `[amazed]` `[angry]` `[excited]` `[sarcastic]` `[curious]` `[bored]` `[tired]` `[scornful]` `[shouting]` `[deep and loud shouting]` `[asmr]` `[panicked]` `[trembling]` `[mischievously]` `[empathetic]` `[whispers]` `[reluctantly]` `[crying]` `[serious]` `[very slowly]` `[very fast]` —— 作用于其后所有文字，直到遇到下一个
- **拟声标签** 7 个：`[gasp]` `[sighing]` `[clears throat]` `[giggles]` `[laughing]` `[cough]` `[snorts]` —— 只在插入位置产生一次效果

```
[excited]今天的天气真不错！[laughing]我们一起出去玩吧！
```

情感标签会跨句自动继承 —— 本工具按句合成，若不补齐则只有第一句带情绪。切到不支持标签的模型时，文本框里的标签会被自动删掉（`[1]` 这类普通方括号保留）。标签栏旁的 `?` 里内置了口播稿生成提示词。详见 [使用说明.md](../使用说明.md) 和 [口播稿提示词.md](../口播稿提示词.md)。

### 自动加情感标签

标签栏下方三个入口，结果一律**先弹窗预览、点「应用到文本框」才生效**，并保留快照供撤销：

- `POST /api/tts/tag` —— 给已有稿子插标签
- `POST /api/tts/script` —— 按主题写一篇新的带标签稿子
- 「快速标注」—— 纯前端关键词规则（`static/js/tag_rules.js`），不联网

拆成三层，各管一件事：

| 模块 | 职责 |
|---|---|
| `server/llm.py` | 通用能力：配置解析、模型白名单、`POST {base}/chat/completions`、错误映射。对「标签」零知识 |
| `server/tagger.py` | 只管提示词与清洗。标签清单**从 `voices.CONTROL_TAGS/RICH_TAGS` 运行时拼**，不再硬编码第三份 |
| `server/api_tagger.py` | 路由、pydantic 校验、限流 |

三个设计取舍：

1. **走裸 HTTP 而不是 dashscope.Generation。** 那个 SDK 只会打百炼；裸 HTTP 则对 DeepSeek、Kimi、GLM、OpenRouter、自建 vLLG 一视同仁。默认 base URL 指向百炼 compatible-mode，所以默认路径下代码也只有一条。
2. **模型 id 必须过服务端白名单**（`llm.resolve_model`），浏览器不能指定任意上游模型 —— 与 `tts_support.normalize_params` 丢弃未知参数是同一个理由。
3. **`sanitize()` 是必需的，不是装饰。** 模型会编造引擎不认识的标签（会被当普通文字念出来）、裹代码围栏、加「好的以下是…」，偶尔还会顺手改稿。因此：非白名单的 `[...]` 一律删除（用户自己原文里的 `[1]` 例外，按原样保留），围栏与客套剥离，并做一次「去标签后是否与原文逐字相同」的**防改写检测**，不一致就在预览里报警。
4. **`LLM_BASE_URL` 不出现在任何公开接口。** `/healthz` 无鉴权，自建 vLLM 的内网地址不该被看到；`/api/config` 只下发模型 id、显示名和一个 `configured` 布尔值。

### 重新生成与种子

`record.params` 在 `createRecord()` 时算好就冻结，`runSentence()` 每次都发同一份。因此同种子 + 同文本 = 逐字节相同的音频，「重新生成」会变成一个点了没反应的按钮。

`app.js` 的启动序列（登录门禁 → 配置加载 → 加载页签）现在有覆盖，办法是给 `boot()` 加 `typeof document !== 'undefined'` 守卫让它能进 node --test，再用 `tests/js/dom_stub.js` 手写一个最小 DOM。`tests/e2e_boot.mjs`（`npm run e2e`）更进一步：拉起真 uvicorn，用真 app.js 跑一遍，验证「有会话 cookie 时不再弹密码框」和「FormData 能被 FastAPI 解析」。两次上线的事故单元测试都看不见，只有这道检查能拦。

`api()` 同理抽到了 `static/js/http.js`：`app.js` 在 import 期就调 `boot()` 并碰 `document`，模块本身没法进 `node --test`。这个模块里两处行为都是**静默失败**，所以值得单测：FormData 被标成 `application/json` 会丢掉 multipart 边界、后端返回 422 而 `detail` 是数组（`new Error(数组)` 会变成 `[object Object]`）。

指令拼装同理抽到了 `static/js/instruct.js`：合成页和复刻页都要发指令，模板差一个字就会变成 428，看起来像音色坏了。

解法是把种子拆成两层，逻辑放在纯模块 `static/js/seed_policy.js`（和 `tag_rules.js` 一样抽出来是为了能单测 —— `tab_tts.js` 依赖 `app.js`，而后者在模块顶层就碰 `document`，Node 里 import 会炸）：

- **基线种子** `record.params.seed` —— 首轮生成沿用它。留空时也会显式生成一个随机值并记下来，这样输入框里的「随机」占位符名副其实：任何一次生成都可复现，用户把数字填回去就能重来
- **单句种子** `sentence.seed` —— 之后每次重新生成都换一个新的。首次判断用 `sentence.seed == null` 而非 `=== undefined`，因为句子要过一遍 IndexedDB，字段可能变成 `null`，两种都表示「还没生成过」

记录卡副标题显示基线种子，单句「重新生成」的 tooltip 显示该句实际种子。

### 文本框的撤销

「撤销」统管所有改动文本框的操作：应用 AI 标签、去标签、清空文本。用栈（上限 20 步）而不是单槽，否则「先打标签再清空」只能撤一步。它放在生成按钮那一行而不是标签栏里 —— 标签栏只在 qwen 模型下显示，藏进去的话切到 cosyvoice 后清空文本就不可逆了。

逻辑抽到了 `static/js/script_box.js`，合成页和复刻页共用同一个实例构造器。共用不是为了少写几行：复刻的生成文本同样能打情感标签和去标签，两边的按钮行为只要有一处不同步，用户就会按记忆里的那个去操作另一个。点标签 chip 也走了同一个入口（`insertTag`），所以「插标签也能撤销」不会只在一个页签成立 —— `source_invariants.test.js` 里有一条不变量专门守这个：页签不许再直接调 `insertAtCaret`。DOM 从外面注入，所以 `tests/js/script_box.test.js` 能直接测栈的行为，不需要浏览器。

每次写值都 `dispatchEvent(new Event('input'))`：两个页签的「去标签」按钮都靠 `input` 事件同步 disabled 状态，直接 `textarea.value = ...` 会让按钮停留在「可点」但其实没东西可去。

### 音色下拉的「最近使用」

`static/js/recent.js`。合成页 253 个音色分 12 组，复刻页每复刻一个多一个，「找回上次用的那个」是最常重复的动作，所以两个下拉最上面都插一组「最近使用」（上限 5 条，最近的排最前，存 localStorage：`recent.ttsVoice` / `recent.cloneVoice`）。

两个容易做错的地方：

- **分组里的条目是 `<option>` 的克隆**，不是重新拼的字符串。标签上的能力角标（`〔情感 场景〕`）由目录渲染时生成，另写一份必然漂移
- **记忆里的音色不属于当前下拉就丢掉**。音色和模型是绑定的，换模型后留着一个别的模型的音色，只会在合成时报「音色与模型不匹配」；复刻音色被删掉同理。过滤之后如果一条都不剩，就退回模型默认音色，`最近使用` 分组也不出现

localStorage 全程可缺省：隐私模式、沙箱 iframe、被人手改坏的值都返回空列表，页面上什么都不显示，功能不报错。纯函数 + 注入 storage，所以这些分支在 `tests/js/recent.test.js` 里都能覆盖。

### 标签弹窗为什么必须是一个共享模块

AI 加情感标签 / 快速标注 / AI 写口播稿这三个入口复刻页也要，而 `<dialog>` 在 `index.html` 里只有一份。驱动它的约 300 行因此搬到了 `static/js/tag_dialog.js`，由 `createTagTagger({ textarea, scriptBox, supportsTags, readOptions, report, label })` 生成绑定好的三个入口。

关键在于**每个页签的信息都是打开弹窗时才给的**。一个写死 `el('tts-text')` 的 apply 处理函数在复刻页会安静地写错文本框：弹窗说「已插入 N 个标签」，屏幕上的字没变。除了目标文本框，`supportsTags()` 也要在 apply 的那一刻重新问一遍 —— 弹窗开着的时候换了模型，标签会被当成字面文本念出来。弹窗自己的按钮由模块**懒挂一次**（`wired` 标记），两个页签各建一个 tagger 也不会让一次点击跑两遍处理器；`tests/js/tag_dialog.test.js` 里「applies into whichever box opened it」和「wires … exactly once」两条守的就是这个，`source_invariants.test.js` 另外从源码层禁止页签自己挂那几个 id。

配套的 `static/js/dom.js` 装着 `el()` 和 `state` 两个原本在 app.js 里的东西。原因很实际：`app.js` 在 import 期就 `boot()`，碰 document 也发请求，任何 `import ... from './app.js'` 的模块都进不了 `node --test`。多一个 `el` 在别处同样等于多一份会漂移的实现，所以搬家而不是复制 —— tab_dialog 因此可以被真正测到。

### 429：把上游状态码翻成人话，然后退避重试

限流是被百炼限流时（`{"error": {"type": "limit_requests", ...}}`）返回 HTTP 429，界面上曾经显示的是 `模型 X 调用失败（HTTP 429）: {"error": {"message": "You have exceeded...` —— 截断在半个 JSON 上。现在 `server/llm.py` 的 `_friendly_error()` 把上游状态翻成一句可执行的中文：

| 上游 | 给浏览器 | 说明 |
|---|---|---|
| 429 | **429** + `Retry-After: 30` | 唯一透传的状态：语义就是「等一下」，前端据此解释自己，文案里点名可换的模型和「快速标注」 |
| 401 / 403 / 404 / 5xx | 502 | 各自说清要检查什么（`LLM_API_KEY`、权限、`LLM_MODELS`、稍后再试） |
| 其它 | 502 | 只取 `error.message` 那一行（脱敏 + 截到 120 字），不再 `json.dumps` 整坨信封 |

原始响应体照旧只进服务端日志（`redact.log_only`）。注意 `redact.scrub()` 因此多了一个 `limit` 参数 —— 默认 200 是为日志调的，放在人眼前要更短。

重试策略按失败类型分开，因为两类需要**相反**的对待：

- **429** —— 账号这一分钟的额度没了。百炼按主账号维度合并所有业务空间与 Key 的调用量，限流通常一分钟内恢复，并且还有一条「请求量突增触发的稳定性保护，即使 RPM/TPM 未超限」。所以只重试**一次**、等 `LLM_RATE_LIMIT_BACKOFF_SECONDS`（默认 20s）。上一版用 3s 退避连打三次，正好踩在突增保护上 —— 被限流时补刀只会让限流更久，这是不该犯的错。
- **5xx / 连接错误** —— 对方服务抖动，与额度无关。退避重试 `LLM_MAX_RETRIES`（默认 2），`LLM_RETRY_BACKOFF_SECONDS`（默认 3）翻倍并带抖动。
- **4xx 其余** —— key 错、模型不存在，重试不可能成功。
- **超时**故意不重试：单次已经 120s，三次是 360s，Vercel 函数 300s 就被回收 —— 那会把一条读得懂的报错换成什么都没有。

另外把本地标注限流从 20 次/60s 收到 **8 次/60s**（`TAGS_LIMIT_MAX_ATTEMPTS`）。它的第二个作用不是防刷，而是别让自己的上游额度被自己打爆 —— 这个数字必须明显低于账号的真实 RPM，否则它只是个「随便点」的量。

### 默认标注模型为什么只列实测调得通的两个

一次 Key 白名单的排查，不是限额问题。

百炼现在签发的都是 `sk-ws-` 开头的业务空间 Key，**带模型白名单**。不在名单里的模型报的**不是** 404「模型不存在」，而是 403 `AccessDenied: Access denied by API-Key restrictions.` 同一把 Key 上的实测结果：

| 模型 | 结果 |
|---|---|
| `qwen3.8-flash` / `qwen3.7-flash` | 200 |
| `qwen-turbo` | 白名单内，但持续 429（限流） |
| `qwen-flash` / `qwen-plus` / `qwen3.6-flash` / `qwen3.5-flash` / `qwen-max` / `qwen3-max` / `qwen3.8-max` / `deepseek-*` / `kimi-*` / `glm-*` | 403 |

公共端点和工作空间端点结果一致 —— 所以这不是端点选错，加 `DASHSCOPE_WORKSPACE_ID` 解决不了。

两个必须记住的坑：

1. **`GET /compatible-mode/v1/models` 不能用来判断可用性。** 它返回全站目录（约 200 个模型），不做白名单过滤，看着什么都有，`/models` 200 只说明 Key 本身有效。
2. **下拉列表里摆一个调不通的模型，等于摆了个「点了就报错」的选项。** 所以默认列表只保留两个实测 200 的同档模型（`qwen3.8-flash` / `qwen3.7-flash`），而不是按价格或能力排一条长列表。要用别的模型：百炼控制台 → API-KEY 管理 → 选中这把 Key 放开，然后往 `LLM_MODELS` 追加 `id:显示名` 即可，前后端代码不用动。

（历史：这一项原先是 `qwen-turbo` → `qwen-flash`，理由是 `qwen-turbo` 已被列入下线批次、公告日 2026-10-10，官方下线机制写明「下线公告发布后 QPM/TPM 会逐步下降」，症状就是「之前正常，突然 429」。`qwen-flash` 输入 0.15 元/百万、RPM 30000、TPM 1000 万，`qwen-turbo` 是 0.3 元/百万、RPM 1200、TPM 500 万。但换掉 turbo 解决不了白名单问题 —— `qwen-flash` 在带白名单的 Key 上同样 403。）

弹窗那侧：`withLoading()` 收的从一个 promise 改成一个 `request()` 函数，失败时把它存成 `retryAction`，错误屏上的「应用到…」藏起来（此时 `pendingResult` 为空，那个按钮点了必然没反应），换成「重试」。写口播稿的主题、时长、语气、听众因此都还在，不必重填。超过 5 秒没有响应会把「模型正在处理…」换成「模型响应较慢，仍在等待…」，免得重试的那几秒看着像卡死。

## 界面上的两个教训

**`index.html` 里 id 重复不会被浏览器告诉你。** 合成页曾有两个 `id="tts-status"`：`getElementById` 只认最后一个，上面那个「未连接」于是永远不变，连接状态和报错全都写在下面那条上。`tests/js/source_invariants.test.js` 现在同时断言「id 不重复」和「`static/js` 里 `el('…')` 引用的 id 在 index.html 里都存在」—— 后者还能挡住更常见的一类事故：标签页重排后拼错 id，`el()` 返回 null，`init()` 抛异常，而 `app.js` 只是把「tab_xxx.js 初始化失败」写在右上角的徽章里，一个页签悄悄死掉。

**手机端的字号不是审美问题。** 全局 14px 时，iOS 一聚焦输入框就把整页放大，而且失焦也不缩回去（Safari 的行为），于是每次打开都要手动缩回来。`@media (max-width: 760px)` 里把控件字号提到 16px、点按高度提到 40px。顶部标题栏和页签包在一个 `.chrome` 里做吸顶：滚动时不用往回滑才能换页签。

## 安全说明

- API Key 只在服务端，浏览器拿不到
- 语音 Key 与文本标注 Key 是**两个独立凭据**，`redact.scrub` 两个都逐字脱敏 —— 换模型厂商后上游报错回显新 Key 也不会漏出去
- 标注接口按 IP 限流（`TAGS_LIMIT_*`），防止刷接口烧 token；限流计数不分成功失败，成本两种情况都已经产生
- `normalize_params` 对非有限数值（`"nan"` / `"inf"`）直接丢弃。`float()` 接受它们不报错，但紧接着的 `int()` 会抛未被捕获的 `ValueError` / `OverflowError`，那会让一个畸形帧变成 500 而不是被夹紧
- `/media/{name}` 无鉴权，因为 DashScope 回源下载时无法带 Cookie；文件名是 uuid4 十六进制，且复刻完成即删除
- 音色配额有限，建议定期清理（对应 `run.py:66-69` 的 `delete_voice_by_prefix`）
- 复刻他人音色前请确认已获得对方同意
